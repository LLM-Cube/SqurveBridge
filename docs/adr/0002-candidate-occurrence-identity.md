# 候选实例身份与 SQL 内容身份分离

Status: accepted

独立采样即使生成完全相同的 SQL，也保留不同候选实例身份；SQL 内容允许通过产物引用共享。采用这一划分而非用 SQL hash 标识候选，是为了保留各次生成的成本、分支和来源，并允许评测分别分析采样行为与内容重复。

优化调用单独保留尝试身份；SQL 无变化时沿用候选，发生变化时创建新候选并关联输入候选。此规则使无效优化尝试仍可审计，同时避免它们被误算为新候选。代价是消费端必须分别处理候选、内容和操作尝试，不能从其中一个数量推断另一个。

变换是否无变化由持久化的提取后 SQL 文本精确相等判定，包含空白、大小写和注释。规范化不参与身份判定，以避免身份规则随 SQL 方言或规范化策略变化；代价是格式变化也会增加候选实例，需在诊断层另外分析内容相似性。
