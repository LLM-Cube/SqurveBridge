# 运行采集与评测验收分别判定

Status: accepted

运行证据用于还原已发生路径、检查 Actor 决策时可见的信息，并在必要外部证据可用时离线重算派生信号，不承诺确定性重放。Runtime 保存观测事实，Evaluation 派生信号；该边界避免采集协议绑定特定评测公式或改变原方法行为。

采集契约采用 REQUIRED、CONDITIONAL、OPTIONAL、OPT_IN 四级要求，并显式区分字段缺失原因。采集故障按 fail-open 原则隔离于业务执行；严格评测在证据门禁拒绝不满足必要证据要求的指标或运行，不以采集异常改写 Actor 执行结果。执行、证据、评测状态分别保留，以换取在业务成功时仍可能无法完成评测这一明确限制。

该选择避免将日志写入可靠性作为模型调用成功的前提，同时要求消费端承担依赖检查，不能再用运行成功或空值默认推断证据完整性。

严格验收依据运行前声明且带版本的 acceptance profile，分别检查必需指标与证据要求。运行验收失败仍保留独立有效的指标；不得事后弱化要求以通过验收。采集同时受到内存、队列、产物体积和写入等待上限约束，避免以无限阻塞换取完整性；超限造成的证据缺口必须显式记录。
